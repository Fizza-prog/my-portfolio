Portfolio Website Specification
1. Project Goal
Build a professional, production-ready personal developer portfolio website.
The portfolio should present me as a developer who builds and ships full-stack products with a focus on clean code, reliable systems, and usable interfaces.
The website should be:
Professional
Clean
Responsive
Accessible
Fast
Easy to maintain
Deployable as a production website
Structured so it can be extended later
This is a React frontend project. A backend is NOT required for the initial version.
2. One-Line Claim
I build and ship full-stack products with a focus on clean code, reliable systems, and usable interfaces.
Do not replace this with generic developer portfolio language unless explicitly requested.

15. Accessibility Requirements
Use semantic HTML where appropriate.
Examples:
nav
main
section
header
footer
button
a
Interactive elements must be keyboard accessible.
Images should have meaningful alt text when appropriate.
Do not use clickable div elements when a semantic interactive element is available.
Maintain sufficient text/background contrast.
16. Performance Requirements
Keep the application lightweight.
Avoid unnecessary dependencies.
Optimize large images before using them.
Avoid unnecessary React state and effects.
Do not add libraries simply because they are available.
The final application should produce a successful production build with:
npm run build
17. Code Quality
Code should be:
Readable
Maintainable
Componentized appropriately
Reusable where useful
Data-driven where appropriate
Free from unnecessary abstraction
Do not over-engineer a simple portfolio.
Prefer simple solutions when they are sufficient.
18. AI Development Rules
AI will be used as a development assistant.
AI may assist with:
Requirement analysis
Architecture suggestions
Component implementation
CSS implementation
Debugging
Refactoring
Accessibility review
Responsive design review
Code quality review
AI-generated code must be reviewed manually before being accepted.
Do not blindly copy large generated implementations.
Manual corrections and refactoring should be documented during development.
19. AI Documentation
Maintain a separate file:
AI_PROMPTS.md

Examples:

Architecture planning
Component implementation
Debugging
Responsive design
Accessibility review
Refactoring
Do not document every trivial autocomplete interaction.
